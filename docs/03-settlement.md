# Fact Sheet 03: 이커머스 정산 / 매출 분석 Micro-B2B SaaS

> **문서 목적**: Project Pinpoint의 후보 영역 #3인 **정산 / 매출 분석** 시장에 대해 검증된 데이터 기반 분석 및 팩트 조사를 기록한다.
> **최종 업데이트**: 2026-08-10
> **상태**: Phase 2 팩트시트 작성 완료 (우선순위 판정 대기)

---

## 1. 개요 (Executive Summary) & 판정 결론

- **핵심 문제**: 이커머스 셀러들은 네이버 스마트스토어, 쿠팡, 지그재그 등 마켓별로 완전히 상이한 정산 주기(쿠팡의 주정산 분할 지급 등)와 복잡한 공제 구조(카테고리 수수료, 서버 이용료, 광고비, 매출 연동 수수료)로 인해 **"매출은 늘어나는데 왜 통장 잔고는 비어있는가?"**에 대한 답을 내지 못함. 주문 건별 실시간 마진율 계산(역마진 진단)이 불가능하고, 마켓의 정산 오류(반품 배송비 환급 누락, 초과 수수료 공제 등)를 수기로 대조하지 못해 발생하는 손실이 상당함.
- **시장 기회**: 기존 자금 관리 솔루션(셀러봇캐시)은 자금 흐름 예측과 선정산 연계에 집중되어 있고, 재무 솔루션(그랜터)은 일반 기업 회계 중심이라 셀러 특화 기능이 약함. 또한 주문관리 솔루션(샵마인)은 가정보 주문처리에 특화되어 있어 정밀 손익 분석이 단절됨. **"주문 단위 실시간 역마진 모니터링 + 마켓 정산 누락/공제 오류 자동 탐지(Audit)에 특화된 초간단 SaaS"**의 공백이 뚜렷함.
- **판정 결론**: **[고득점 추진 후보 (우선순위 2순위)]** — 셀러들의 생존(돈의 흐름 및 역마진 방지)과 직결된 치명적인 페인포인트를 해결함. 마켓 API 수집 인프라 구축의 허들이 있으나, 백엔드 복식부기(Double-Entry) 원장 모델 설계와 비동기 정산 대조 알고리즘을 활용해 카피하기 힘든 기술적 장벽을 구축할 수 있음.

## 3. 셀러의 실제 비용 및 시간 소모량

### 3.1 시간 소모량
- **정산 대조 및 손익 정산서 작성**: 매월 말 **4시간 ~ 8시간** 소모 (셀러 커뮤니티 정산 수기 대조 공수 설문 기준).
  - 마켓 백오피스 로그인 → 정산서 다운로드 → 엑셀 VLOOKUP으로 주문 ID와 매칭 → 마켓 수수료 검증 → 반품/취소 건의 입금 및 환급 데이터 검토 → 수기 마진율 재산정.
- **광고비 및 부대비용 귀속**: 매월 결산 시 **3시간 ~ 5시간** 소모 (셀러오션 커뮤니티 리서치 데이터 기준).
  - 네이버/쿠팡 광고 센터에서 사용한 광고비를 다운받아 개별 상품별 판매 기여도에 따라 나누고 배분하는 수기 계산.
- **역마진 인지 지연**: 제품 사입가 상승, 배송비 인상, 쿠팡의 다이나믹 최저가 매칭 및 광고비 초과 소진 시 **즉시 알지 못하고 부가세 신고나 분기 결산 시점에야 역마진임을 발견**하는 정보 격차 시간 발생.

### 3.2 비용 소모량
- **미정산/오공제 방치로 인한 손실**: 연간 평균 **약 50만 원 내외** (정산 대조 솔루션 사별 실제 적발/환급 데이터의 보수적 평균치).
  - 마켓이 반품 배송비를 셀러에게 환급해 줘야 하는데 정산 시스템 오류로 누락되거나, 프로모션 지원금 공제 비율이 잘못 적용되어 정산금에서 초과 공제된 비용을 인지하지 못해 공중분해됨.
- **대행/회계 솔루션 구독료**: 다채널 및 광고 통합 분석 시 월 **10만 원 ~ 20만 원** 상당의 복수 툴 구독 비용 발생.

## 4. TAM / SAM / SOM 산정

```text
[TAM - 전체 시장]
국내 이커머스 실질 액티브 셀러 약 30만 명 (통신판매업 신고 기준 스마트스토어/쿠팡 중복 제거 활성 판매자 추정치)
→ 30만 명 × 월 4만 원 ($29) × 12개월 = 연 1,440억 원

[SAM - 유효 시장]
월 매출 3천만 원 이상으로 3개 이상의 다채널 분산 판매 및 광고 집행을 활발히 하는 중소형 셀러 (약 15%) = 4.5만 명
→ 4.5만 명 × 월 4만 원 ($29) × 12개월 = 연 216억 원

[SOM - 목표 시장 (Micro-B2B SaaS)]
초기 목표 셀러 500명 (월 구독 전환)
→ 500명 × 월 $29 = MRR 2,000만 원 ($15K MRR)
```

## 5. 기존 도구의 가격대 및 핵심 페인포인트

### 5.1 기존 도구 가격 구조
- **정산 특화 솔루션**: 월 49,000원 ~ 100,000원 수준으로 1인 및 소형 셀러(월 매출 1천만~3천만 원)에게는 매달 고정비로 지출하기에 다소 문턱이 높음.

### 5.2 셀러들의 핵심 페인포인트 (커뮤니티 및 현장 피드백)
1. **"언제, 진짜로 얼마가 입금되는지 모르겠다"**:
   - 쿠팡의 주정산(구매확정 기준 70%는 15영업일 후, 30%는 익익월 정산) 및 타 마켓의 상이한 정산 주기가 얽혀 자금의 정확한 캐시플로우 예측이 불가능함.
2. **"마켓 수수료와 숨은 공제비가 블랙박스다"**:
   - 매출 연동 수수료, 연령별/결제수단별 PG 수수료, 마켓 분담 할인 쿠폰 비용 등이 정산서의 복잡한 공제 항목으로 표기되어 역마진 여부를 가려내기 매우 까다로움.
3. **"반품 및 환불 프로세스 시 정산 누락에 무방비하다"**:
   - 반품 처리 시 고객 환불은 즉시 이루어지나, 마켓이 셀러에게 반품 배송비를 입금해 주는 과정에서 정산이 누락되거나 지연되는 현상을 수작업 엑셀 대조 없이는 적발할 수 없음.

## 6. Project Pinpoint +1 차별화 전략 (Hookable Formula)

```text
[기존 손익/재무 솔루션 (셀러봇캐시/그랜터)]
"계좌/카드와 마켓의 자금 흐름을 보여주고 세무 증빙 및 선정산을 지원합니다. (월 5~8만 원)"

                    ▼ (Hookable +1 차별화)

[Pinpoint Settlement Auditor]
"마켓 API 연동 1초. 개별 주문별 실시간 '진짜 마진'을 추적해 역마진을 경고하고, 마켓이 누락한 반품비와 초과 공제금을 자동 추적(Audit)해 드립니다. (월 $29 단일가)"
```

### 핵심 +1 차별화 요소 3가지

1. **상품/주문 단위 실시간 역마진 진단 (Real-time Margin Watcher)**:
   - 주문이 들어오는 즉시 `[판매가 - (사입가/원가) - 카테고리 실질 수수료 - 주문에 매핑된 실시간 광고비]`를 자동 연산하여 실시간 마진율을 모니터링하고 역마진 발생 시 즉시 대시보드 및 카카오 알림톡 경고 발송.
2. **미정산 및 오공제 탐지 엔진 (Audit Linter)**:
   - 마켓 API 데이터를 1원 단위로 분석해 마켓 측 시스템 오류나 정정 누락으로 인한 반품 배송비 미입금 건, 계약 대비 과다 공제된 수수료 건을 자동 적발. 소명에 필요한 "마켓 고객센터 이의제기용 데이터 템플릿"을 1클릭으로 생성하여 손실 복구 지원.
3. **일별 정산 캐시플로우 예측 달력 (Cash-flow Calendar)**:
   - 각 마켓의 정산 주기와 보증금율(쿠팡 30% 유보금 등)을 시뮬레이션 모델에 대입하여, 향후 30일간 매일 내 통장에 실제로 꽂히는 총정산 금액을 오차 범위 5% 이내로 리포팅.

## 7. 백엔드 엔지니어링 구현 포인트

- **Double-Entry Ledger 기반 정산 검증 (더블엔트리 원장 아키텍처)**:
  - 마켓의 단순 정산 합계액만 비교해서는 누락이나 오류를 잡아낼 수 없음.
  - 개별 **주문 ID(Order ID)**를 고유 키(Unique Key)로 삼아 주문 시점의 매출 채권(Debit)과 실제 정산 입금액/공제 비용(Credit)을 복식부기(Double-Entry) 형태로 원장에 기록하고, 대차대조 차액이 발생하는 주문 건을 필터링하는 데이터베이스 파이프라인 구축.
- **광고비 실시간 상품 귀속 알고리즘 (Ad Spend Attribution)**:
  - 네이버 쇼핑검색광고 API, 쿠팡 광고 API를 통해 캠페인별/키워드별 광고비 데이터를 주기적으로 수집.
  - 광고 소재의 상품 ID 및 형태소 분석기(Mecab)를 활용한 상품명 매칭을 통해 광고 집행 비용을 개별 상품 원장에 실시간 변동비 항목으로 반영하는 계산 배치 모듈 구축.
- **다채널 대량 정산 데이터 수집 (비동기 ETL 파이프라인)**:
  - 수십 개의 쇼핑몰 API로부터 주문, 취소, 반품, 정산 상세 내역(일평균 수만 건)을 수집하기 위해 Redis와 BullMQ 기반의 분산 ETL 큐(Queue) 시스템 구축. 마켓 API 서버의 Rate Limit 제한 준수 및 예외 발생 시 재시도(Retry) 오케스트레이션 설계.

## 8. 성공/실패 검증 지표 (Validation Metric)

- **MVP 개발 기간**: 2주
- **초기 검증 목표**:
  - 랜딩페이지 가입 셀러 70명 확보 (2주)
  - 베타테스트 진행 후 **유료 전환 셀러 12명** (월 3.9만 원 / MRR ~45만 원)
- **성공 판단 기준**: 3개월 내 유료 회원 50명 달성 ($1.5K MRR) 및 누적 미정산 적발 금액 1,000만 원 돌파(사회적 증거 확보).
